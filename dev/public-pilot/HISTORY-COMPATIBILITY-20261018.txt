Unpublished DEV candidate: cloud history compatibility, 2026-10-18
Base: a18d166. No rules/configuration/feature gate changes.

History API now uses document-ID ordering, limit(50), and snapshot cursors to
read every page of tournament, owned casual and personal receipt queries.
Account identity is checked around each page and linked-record read.
Default listMyResults() remains strict. Accounts opts into an onUnavailable
callback: explicit permission-denied on tournament queries or old linked
casual record reads may yield partial history, with the inaccessible sources
named visibly and in JSON export (historyComplete/unavailableSources).
Network errors, invalid stored records, missing receipt targets and session
changes still fail; they are not relabelled as empty/complete history.
Denied owned-history/receipt-list queries remain errors.
No cloud or local history is deleted or rewritten by these reads.

Recording setup explains the proposed private-history scope: 501/Cricket,
exactly the signed-in scorekeeper's own account linked. Other players can
remain unlinked guests. Multiple linked players, other-only attribution or
other game types require explicit acknowledgement of local recording. Setup
never deselects another player to satisfy the scope. Consent to write someone
else's private history is not inferred from a profile choice or QR identity.
Save preflight for out-of-scope pending records preserves every participant,
ledger, result ID, undo/redo state and pending local copy; it submits no cloud
write. Existing self-only 501/Cricket save paths remain available when gates
are enabled. Released gates remain unchanged/off. Shared-tablet tournament
submission and active-game cloud resume code are untouched.
